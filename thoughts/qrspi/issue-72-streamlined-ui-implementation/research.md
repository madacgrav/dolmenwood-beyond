# Research Findings

All paths relative to `apps/web/src` unless noted. Verified against the working tree on 2026-07-18.

## Q1: Design tokens, consumption, theme switch

### Findings
- Tokens in one `@theme` block (`app/globals.css:6-25`): 9 colors (`--color-bg/surface/primary/primary-hover/text/text-muted/gold/danger/border`, `:6-14`), 3 fonts (`--font-display` Cinzel, `--font-body` Satoshi, `--font-mono` JetBrains Mono, `:17-19`), 3 radii `--radius-sm/md/lg` 4/8/12px + `--touch-target 44px` (`:22-25`). **No spacing, shadow, or font-size tokens.**
- Consumption is exclusively inline `style={{ ... 'var(--color-*)' }}` — grep: 1412 `var(--color|--radius|--font-` hits across 153 files, all inline style props. **Zero Tailwind utility consumption** (`bg-primary`, `bg-[--color-*]`, etc. — 0 matches) despite Tailwind v4 `@theme` generating them.
- `--radius-*` never consumed via `var()` outside globals.css; components hardcode literal px (`10px`, `8px`, `14px`). `--touch-target` used once: global `button,[role=button],a { min-height: var(--touch-target) }` (`globals.css:90-95`).
- Dark theme: same 9 colors duplicated twice — `@media (prefers-color-scheme: dark)` scoped `:root:not([data-theme="light"])` (`globals.css:29-41`) + `[data-theme="dark"]` (`globals.css:44-54`).
- Toggle UI: `app/(app)/settings/components/AppearanceSection.tsx` — Light/Dark/System buttons (`:24-51`); `handleThemeChange` (`:12-22`) sets/removes `data-theme` on `<html>` and persists to `localStorage['dolmenwood-theme']` (`:14`). **No bootstrap re-applies the stored choice on page load** — initial `useState` (`:7-10`) only highlights the button; until a button is clicked, appearance is governed solely by the OS media query.
- Fonts loaded in root `app/layout.tsx`: `Cinzel` → CSS var `--font-cinzel` (`:5-9`), `JetBrains_Mono` → `--font-jetbrains` (`:11-15`), applied on `<html>` (`:42`). **Disconnect:** `--font-display` is the literal string `'Cinzel', 'Georgia', serif` — not wired to `var(--font-cinzel)` — so the dozens of components using `var(--font-display)` get local/system Cinzel or fall to Georgia; only the 4 auth pages referencing `var(--font-cinzel)` directly (`(auth)/sign-in/page.tsx:33` etc.) use the next/font-loaded webfont. `--font-body` Satoshi has **no font load at all**. `--font-mono` never consumed anywhere despite JetBrains Mono being loaded.
- Other globals: keyframes `pulse/diceShake/celebrationBounce/levelUpPulse/spin` (`globals.css:63-87`); `.wp-content` news-HTML styles (`:97-108`).

## Q2: `(app)` page frame — shared vs per-page

### Findings
- `app/(app)/layout.tsx` (33 lines): async server component, `force-dynamic` (`:6`). Reads `auth()` (`:9`); fetches account for `isAdmin` (`:11-15`).
- **Fixed top header** rendered only if session (`:19-27`): 52px, `zIndex:50`, surface bg, bottom border, right-aligned — content is `<NotificationBell/>` **only**. No title, back button, logo, or `env(safe-area-inset-top)`.
- `<main>` (`:28`): `flex:1`, `paddingTop: session ? 52px : 0`, `paddingBottom: 80px`. `<BottomNav>` rendered **unconditionally** (`:29`) — not session-gated, unlike the header.
- `components/layout/BottomNav.tsx`: client, `usePathname` active match via `pathname.startsWith(href)` (`:48`). Items (`:12-20`): 🏠 Characters, 📜 News, ⚔️ Campaign, 🎲 Dice, ⚙️ Settings, +🛡️ Admin if `isAdmin`. Fixed bottom, **80px**, `zIndex:50`, `env(safe-area-inset-bottom)` (`:44`), 44px touch targets, active = `--color-primary` + bold.
- `components/notifications/NotificationBell.tsx`: fetches on mount (`:24-31`), unread badge (`:54-64`, danger bg), dropdown `top:52px` (hardcodes header height), 280px wide, `zIndex:60` (`:67-98`); item click marks read + refetch (`:35-40`).
- **Layout provides no max-width, no h1, no page padding.** Grep `maxWidth` in `app/(app)`: 20+ pages each define their own container — mostly `600px` but also `900px` (admin:147), `540px` (level-up:159, import:149), `500/420/400/360px` elsewhere; padding varies (`1.25rem`, `1rem`, `1.5rem 1rem`, …). 16 files hand-roll their own `<h1>` with independent inline `fontFamily: var(--font-display)` + varying `fontSize` (1.1–1.75rem): e.g. `settings/page.tsx:37`, `news/page.tsx:15`, `xp-log/page.tsx:71`.

## Q3: Character sheet map

### Findings
- Entry `app/(app)/characters/[id]/page.tsx` (client). Read-only mirror `characters/[id]/view/page.tsx` — owner visiting `/view` is redirected to the editable sheet (`view/page.tsx:46-49`); non-owners get all tabs with `readOnly`/`editMode={false}` + DM XP-correction path (`xpVariant="dm-correction"`, `onCorrectXP` → `correctXP()`, `view/page.tsx:99-113`).
- Tabs `stats|combat|inventory|magic|notes` (`page.tsx:15`), plain `useState('stats')` (`:24`), no URL sync. Tab labels at `page.tsx:105-111` — magic tab labelled **"Magic and Abilities"**. Sticky tab bar, `overflowX:auto`, active = primary + bold + 2px bottom border (`:125` sticky zIndex:10). Bodies conditionally rendered/unmounted (`:155-159`).

- **AC computed once at page level**: `deriveCharacterAC(character, acItems)` (`page.tsx:100`, rules-engine), `acItems` mapped from inventory (`:94-99`); passed as prop to StatsTab + CombatTab, which only consume `acBreakdown?.total ?? 10`. `view/page.tsx:78-85` duplicates this computation independently.
- Header (`character-sheet/CharacterSheetHeader.tsx`): `HeaderTopBar` (back, Edit/Done, ⋮ menu → XP History/Level-up History/Export PDF/Delete; read-only badge variant `HeaderTopBar.tsx:32-43`), `PortraitButton` (64px circle upload), name + `kindred class · Level N` line (`:48-65`), `header/HPBar` (±5/±1 + set), `header/XPBar` (Add/Set, XP-mod preview via `applyXPModifiers`, pulsing "⬆ Level Up!" → `/level-up`; `dm-correction` variant). `hpEditOpen`/`xpEditOpen` mutually exclusive (`:11-12,71,79`).
- **StatsTab** order (`StatsTab.tsx`): AbilityScoresSection, CombatStatsSection (AC/Attack/Speed/Exploring/Overland as `StatPill` row), TraitsSection, SkillsSection, **stats/SavingThrowsSection**, LanguagesSection, RetainersSection (+PromoteRetainerModal, PromoteSuccessToast). Rules-engine derivations at `StatsTab.tsx:33-42` (`getSaveTargets`, `getAttackBonus`, `calculateSpeed`, …).
- **CombatTab** order (`CombatTab.tsx`): ConditionsSection, **combat/ArmourClassSection** (`:57`), AttackSection, AmmoSection (conditional), BattleModal, HitDiceSection, **combat/SavingThrowsSection** (`:89`), MountsSection.
- **Saving-throw duplication**: `stats/SavingThrowsSection.tsx:18-53` = static display of 5 targets + magic resistance; `combat/SavingThrowsSection.tsx:37-103` = tap-to-roll variant (d20 + AnimatedDie + pass/fail badge, `readOnly` hides clear button). - **AC display duplication**: `stats/CombatStatsSection.tsx:21-27` = AC as one of five pills, no breakdown; `combat/ArmourClassSection.tsx:14-32` = big total + breakdown showing **only Base 10 + DEX mod** — the rules-engine `ACBreakdown`'s `armorBonus/kindredBonus/classBonus/shieldBonus` are computed but never displayed (only `ac`, `dexScore`, `dexMod` passed in).
- **NotesTab**: only nested sub-tab bar in app — `SUBTABS = General|Sessions|People` (`NotesTab.tsx:202-232`), same underline pattern; debounced-autosave textarea + dated entry lists.

## Q4: Magic tab detail

### Findings
- Gating (`MagicTab.tsx:16-25`): `isSpellcaster(class)`, `getSpellSlots(class, level)` (returns `{glamours:n}` for Enchanter or rank→count map), `isGlamour = 'glamours' in slotsData` (`:21`), `classHasRunes(class)` (`:22`), `getMagicalKindredTraits(kindred)` (`:23` — filters to `['Glamours','Shape-Shifting','Mad Revelry','Knacks']`, rules-engine `kindreds.ts:70-73`). Empty state "This class has no magical abilities" only if `!spellcaster && magicalTraits.length===0` (`:47-54`).
- **Six sections, fixed order** (`MagicTab.tsx:66-158`): ① KindredAbilitiesSection if `magicalTraits.length>0` (`:70-90`); ② SpellSlotsSection if spellcaster (`:93-103`); ③ PreparedSpellsSection if `spellcaster && !isGlamour` (`:106-117`); ④ SpellBookSection non-glamour mode if `spellcaster && !isGlamour` (`:120-131`); ⑤ SpellBookSection with `isGlamour={true}` if `isGlamour` (`:134-145`) — same component reused, mutually exclusive with ④; ⑥ RunesSection if `hasRunes` (`:148-156`).
- **`kind` discriminator**: `DBSpell.kind?: 'spell'|'glamour'|'rune'|'kindred-glamour'|'knack'` (`lib/api/spells.ts:34`), server allowlist in `lib/data/spells.ts:141-145` (unknown values dropped). Legacy entries without `kind` classified by `entryKind()` — `kind ?? (spell_level===0 ? 'glamour' : 'spell')` (`MagicTab.tsx:28`). `kindredGlamourEntry` falls back to first plain glamour for non-Enchanters (old innate-glamour storage, `:34-36`); `knackEntry` no fallback (`:37`).
- Roll/pick: `onRollGlamour`/`onRollKnack` (`MagicTab.tsx:76-86`) use `pickRandom` over `getSpellsForClass('Enchanter')` / `getKnacks()`; picks use `<select>` dropdowns in `KindredAbilitiesSection` (`:41-42` memoized options). Both funnel into `magic.addSpell(0, name, kind)`. `readOnly` hides pick/roll UI when no entry exists (`KindredAbilitiesSection.tsx:90,167`).
- Data flow: `useSpells` (`magic/use-spells.ts`) → mount `fetchMagicData(id)` (`lib/api/spells.ts:53`) → `GET /api/characters/[id]/magic` → `lib/data/spells.ts:59-62` (authz `requireAccountId` + `assertCharacterOwner`, reads embedded `spellSlots/spellPreparations/spellbook` arrays off `CharacterDoc`). All mutations via single `POST /api/characters/[id]/magic` with discriminated `MagicOp` handled by `applyMagicOp` switch (`lib/data/spells.ts:79-171`) over `mutateOwnedCharacterDoc` (ETag-guarded). Ops: initSlots, updateSlotTotals (auto-init/level-up resync in `use-spells.ts:51-91`), addSpell (`:181-196`, optimistic local append), addPreparation/setPreparationCast (`:134-166`), deleteSpell (`:175-178`).
- `RunesSection` shows tier via `getRuneTier(class, name)` (null for free-text → plain "Rune"). `SpellBookSection` differs between spell/glamour modes only in labels/empty text (`SpellBookSection.tsx:27-39,55-58`).
- `useSpells` skips loading when `!spellcaster && !hasKindredMagic` (`use-spells.ts:100`).

## Cross-Cutting Observations
- **Styling monoculture**: inline `style={{}}` + literal `var(--color-*)` everywhere; the two Tailwind-based `ui/` primitives (Button, Card) are dead. Radius/font tokens declared but effectively unused; two of three font tokens point at fonts that are never loaded, and the loaded Cinzel webfont only reaches the 4 auth pages.
- **Repeated hand-rolled patterns, no abstraction**: page container (varying maxWidth), page h1, sticky underline tab bar (char sheet, view page, campaign, Notes sub-tabs — 4 reimplementations), surface card, fixed-overlay modal (7+ z-index values), input style block, skeleton div, empty state, add-form reveal, chevron collapse.
- **Duplication across owner/view routes**: `view/page.tsx` re-derives AC/carriedWeight and re-declares the tab list rather than sharing.
- **Role model is inconsistent per tab**: Bank gated account-wide (`hasDMCampaigns`), Schedule/NPCs derive per-campaign `is_dm`, Quests ignore roles entirely (server too — participant-only checks), Overview shows both DM and player views to everyone.
- **Mobile-first PWA**: 600px cap, 44px touch targets, `100dvh`, safe-area only on bottom nav, `zIndex:50` shell bars; NotificationBell dropdown hardcodes the 52px header height.
- Delta vs. earlier snapshots in repo: campaign has a 5th Quests tab; Magic tab has 6 sections incl. KindredAbilities/Runes with `kind` discriminator; `ui/NumberField` exists with 2 adoptions; magic tab label is now "Magic and Abilities".
